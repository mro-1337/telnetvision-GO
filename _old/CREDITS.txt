HOW THE COUNTING WAS DONE
-------------------------

Counts are lines of code, not counting blank lines. A line counts as
"from upstream" when it is part of a run of at least 6 lines that
matches the upstream source exactly, apart from indentation. Test files
are counted separately from the program code. Your numbers may be a
little different if you count another way, but the overall picture won't
change.

tvserver's door_*.go files in detail
------------------------------------

  door_render.go   from door/main.go: half-block, shade and 16-color
                   rendering, delta drawing, pacing. 1,420 of its 1,423
                   lines are upstream's; only the program entry was
                   changed to fit tvserver.
  door_audio.go    from door/audio.go: SyncTERM sound commands, clip
                   slots, queueing, sync. 832 of 1,028 lines are
                   upstream's. Changed and added:
                     - per-viewer sound quality and compression;
                     - falling back when a format doesn't play;
                     - volume;
                     - the sound debug counters.
  door_term.go     from door/term.go         (unchanged)
  door_door32.go   from door/door32.go       (unchanged)
  door_io_*.go     from door/io_*.go         (unchanged)

So tvserver.exe contains about 98% of the original door's code.


The one change to service.exe
-----------------------------

service\main.go, line 235:

    upstream:   ch, _, ok := parseString(payload, off)
    fixed:      ch, off, ok := parseString(payload, off)

Upstream threw away the position after the channel name in the
producer's hello, so the byte after it (does this producer send sound?)
was read from the wrong place and the log could report audio wrongly.
Only that log line used the byte, so relaying worked either way.

fTELNET (THE WEB VIEWER)
------------------------

The web viewer runs fTelnet in the browser. tvserver serves it from
tvserver\web\ftelnet.

  - ftelnet.js is fTelnet's own release build (ftelnet.norip.noxfer.js,
    6,164 lines, compiled from about 12,900 lines of TypeScript). It is
    used as it is, apart from 19 changed and 52 added lines (about 1%),
    all made by patch-ftelnet.py:
       1. 24-bit colors that are followed by more parameters work
       2. block characters are drawn as plain rectangles (much faster
          for video)
       3. a size limit on the recolored-font cache
       4. auto-wrap on/off (CSI ?7l / ?7h)
       5. the screen-reader text keeps only the newest 60 lines
       6. a hidden cursor (CSI ?25l) is really hidden
  - The fonts, keyboard files and ftelnet.css are fTelnet's, unchanged.
  - New, not from fTelnet: tvaudio.js (477 lines: sound, sixel, JPEG XL
    and stream filter), index.html (193 lines) and patch-ftelnet.py
    (137 lines).

So of the web viewer's code, about 6,100 lines are fTelnet's and about
810 are new.
