TELNETVISION FOR WINDOWS - WHAT'S NEW
=====================================

VERSION 1.6.2
-------------

  Movie night is now called group chat
    - Everywhere people see it: the viewers' screen ("GROUP CHAT - 3
      here"), the hint line, the web page's Group chat button, the
      camera window and the docs. The keys are the same: N for viewers,
      W on the camera PC.
    - The settings are now GROUP_CHAT (telnetvision.ini) and group_chat
      (tvserver.ini). The old names, MOVIE_NIGHT and movie_night, still
      work (tvserver renames movie_night in its ini the next time it
      starts). Viewers' saved names and colours are kept.

  /name in the group chat
    - Send  /name newname  as a chat message to change your name.
      Everyone sees "Ann is now called Annie"; the new name is
      remembered for next time. A name someone else has is refused.

  Ban lists (tvserver)
    - ipban.txt: addresses that can't watch at all, on telnet or the
      web page. Someone already watching is cut off within seconds.
    - chatban.txt: addresses or chat names that can watch and read the
      chat, but not write in it.
    - Plain text next to tvserver.ini, one entry a line, # for notes;
      203.0.113.5, 203.0.113.* and 203.0.113.0/24 all work. Edits take
      effect within a few seconds, no restart.
    - Server window commands: ban, unban, chatban, unchatban, bans.
    - Chat messages in the server log now show the sender's address.

VERSION 1.6.1
-------------

  Movie night from the camera PC
    - W in the camera window turns movie night on or off for everyone
      (viewers still show or hide the chat for themselves with N).
      MOVIE_NIGHT=0 in telnetvision.ini starts with it off; the status
      line says "movie night off". While it's off, N tells viewers it's
      turned off on the camera PC, and open chats close.
    - The chat shows in the camera window as it happens: messages, and
      who joins and leaves.
    - Both programs changed.


VERSION 1.6.0
-------------

  Movie night (tvserver)
    - Viewers press N (or the web page's Movie night button): the picture
      moves left and a chat opens on the right, shared by everyone on
      the channel in movie night. They pick a name the first time; each
      name gets its own random colour. Enter starts a message, Enter
      sends, Esc cancels. N hides it again. Names, colours and whether
      it was on are remembered. The server window logs the chat.
      movie_night = off in tvserver.ini turns it off.

  Cameras (camera PC)
    - D in the camera window lists the cameras; type a number to switch
      to one, then Y to save it as the default (SOURCE in
      telnetvision.ini), any other key to play it just this time.

  Playing something from the command line (camera PC)
    - telnetvision.exe X:\Movies (or a file, or a URL), or a file or
      folder dragged onto telnetvision.exe, plays that instead of SOURCE
      without changing telnetvision.ini. Several: the first plays, the
      rest join the playlist.

  Both programs changed.


VERSION 1.5.6
-------------

  Fixes
    - Music broke up (stopping and starting) while a viewer had the
      playlist (L) open. Two causes, both fixed:
        - the camera PC sent the whole list - every song's name - to
          tvserver every 2 seconds, which held up the sound behind it.
          Now the names go once when the list opens (and again only if
          they change); after that just what's playing and up next;
        - tvserver redrew the busy picture (the music visualizer) and
          the list over it for every frame. Now the picture holds still
          under the list while it's open; the sound keeps playing.
    - Both programs changed. (Either one alone helps; both is best.)


VERSION 1.5.5
-------------

  Viewers' playlist on/off (camera PC)
    - O in the camera window turns the viewers' playlist (their L key)
      off or on while it runs; VIEWER_PLAYLIST=0 in telnetvision.ini
      starts with it off. The status line says "viewer list off".
    - While it's off, viewers pressing L are told "The playlist is
      turned off on the camera PC", and a list that's open closes.
    - Both programs changed (a 1.5.0-1.5.4 tvserver says "nothing to
      pick" instead).


VERSION 1.5.4
-------------

  Fixes (camera PC)
    - While a big YouTube video downloaded (nothing playing yet), the
      camera PC sent nothing, so tvserver dropped the feed after a
      minute and the window said "connection lost (... wrong TOKEN ...)"
      over and over. Now:
        - viewers see DOWNLOADING FROM YOUTUBE and how far it's got, in
          big letters on the last picture, and the status line shows
          "downloading 45%" first, where it isn't cut off;
        - whenever there's nothing new to send, the last picture is sent
          again every 15 seconds, so the link stays up;
        - "connection lost" now says what actually happened (closed right
          away: check TOKEN; closed after a quiet minute; or the server
          restarted / another camera PC took the channel).
    - Only telnetvision.exe changed.


VERSION 1.5.3
-------------

  Fixes (camera PC)
    - A re-encoded copy of a 10-bit (HDR, x265) movie could fail to play
      ("Error opening output files: Invalid argument") and the movie was
      skipped. Copies are now ordinary 8-bit H.264 (-pix_fmt yuv420p),
      played without the graphics card, and read with a longer look at
      their start to find the sound.
    - If a copy has no sound track, the sound plays from the original
      file; if a copy won't play at all, the original plays from the
      same place instead of the movie being skipped.
    - ffmpeg's error messages now show the reason, not just "Error
      opening output files".
    - tvserver.exe didn't change after 1.5.0; in the full 1.5.3 release
      it's numbered 1.5.3 too, so both programs match.


VERSION 1.5.2
-------------

  Re-encoding (camera PC)
    - Playback now stops until the whole copy is made, then carries on
      from the same place. (Before, it started playing the copy while it
      was still being made, which looked like the original playing on.)
    - The please-wait notice is now in big letters in the middle of the
      picture - RE-ENCODING / PLEASE WAIT / 35% - 4 MIN - on the dimmed
      last picture, for every viewer (characters, sixel, JPEG XL and the
      web page alike), instead of a caption line at the bottom.
    - Only telnetvision.exe changed.


VERSION 1.5.1
-------------

  Re-encoding by hand, and a half-size copy (camera PC)
    - E in the camera window re-encodes the movie that's playing to a
      temporary file and plays that from the same place: 1 = 720 wide
      H.264, 2 = half size, 0 = back to the original file.
    - The 720 copy is made with exactly
        ffmpeg -i movie -vf scale=720:-2 -c:v libx264 -crf 23 -c:a aac
      (no more "-preset veryfast" unless REENCODE_PRESET asks for it),
      and the half-size one with
        ffmpeg -i movie -vf "scale=iw/2:ih/2" -c:a copy
      (sound that can't go into the copy as it is becomes AAC).
    - REENCODE_MODE picks which copy REENCODE=1 makes (720 or half).
    - A movie that plays from a copy keeps doing so after jumps, and
      when the playlist comes round to it again.
    - Only telnetvision.exe changed; tvserver.exe 1.5.0 is current.


VERSION 1.5.0
-------------

  Jumping around in a video (camera PC)
    - J: type a time to go to (1:05:00, 45:00, 90 for minutes, 1h30m,
      or +10 / -5 minutes from here). Left / Right arrow: back / ahead
      5 minutes (SEEK_STEP). Picture, sound and subtitles all carry on
      from there; viewers stay connected.
    - The status line shows where the video is ("12:34 / 1:45:00").

  Re-encoding movies this PC can't decode fast enough (REENCODE=1)
    - When a movie file plays slower than FPS for several seconds,
      ffmpeg makes a lighter copy (H.264, 720 pixels wide, AAC sound)
      from the exact place it had reached, and the movie carries on from
      there once enough of it is made. Viewers see a please-wait notice
      with how far along it is.
    - The copy is a temporary file, deleted when the movie ends or is
      skipped, and when telnetvision closes (left-over copies are
      cleared at the next start).
    - New settings REENCODE, REENCODE_WIDTH, REENCODE_CRF,
      REENCODE_PRESET, REENCODE_FOLDER.

  The playlist for viewers (L)
    - A viewer who is the only one watching presses L for a lightbar
      list of the camera PC's playlist: arrow keys move, Enter plays
      the highlighted entry now, Space tags it to play next (in the
      order tagged). No typing. It closes if someone else starts
      watching. The web page has a Playlist button with on-screen
      buttons for touch screens.
    - N on the camera PC plays the tagged entries first.

  Fixes
    - Option 8 (Auto detail) in the viewers' S menu didn't respond to
      the 8 key.
    - The Win64 README's title said "(32-bit)".
    - Closing the camera window now stops cleanly (ffmpeg, temporary
      files), as Q does.


VERSION 1.4.1
-------------

  Web page
    - Full screen really fills the screen now. Before, the picture stayed
      at its page size (at most 960x575) in the top of the screen; now
      it's scaled up to the largest size that fits, centred on black.
    - Double-click the picture to go full screen and back; an "Exit full
      screen" button sits in the corner (Esc works too).
    - Phones that can't do full screen for web pages (iPhone) fill the
      browser window instead.


VERSION 1.4.0
-------------

  JPEG XL detail
    - JPEG XL viewers pick their detail with S, option 7: High
      (320x192), Medium (240x144) or Low (160x96, about a third of
      High's data). The camera PC makes each level only while someone
      watches at it. New camera PC settings JXL_MEDIUM_WIDTH,
      JXL_MEDIUM_QUALITY, JXL_LOW_WIDTH, JXL_LOW_QUALITY; new
      tvserver.ini setting jxl_detail (where viewers start).
    - Option 7 is now "Detail", for sixel and JPEG XL alike (each keeps
      its own setting).

  Auto detail
    - When a sixel or JPEG XL viewer's connection can't keep up, their
      detail goes down a step by itself (High -> Medium -> Low), with a
      notice along the top, and back up after 30 seconds of keeping up.
      It never goes above what the viewer picked. S, option 8 turns it
      off for a viewer; auto_detail = off in tvserver.ini for everyone.
    - In a test at 0.3 Mbit/s, a JPEG XL viewer went from 4.5 to 15
      frames a second.

  Works with 1.3.0: a 1.3.0 camera PC makes High only (the menu says
  so), and a 1.3.0 tvserver asks a 1.4.0 camera PC for High only.


VERSION 1.3.0
-------------

  JPEG XL pictures
    - New Colors choice "JPEG XL" for terminals that can draw JPEG XL
      (SyncTERM 1.10+ and terminals that copy its commands): real
      pixels, full colour, sharper than sixel at about half the data.
    - The server asks each terminal whether it can draw JPEG XL and
      only offers the choice to those that say yes.
    - The camera PC makes the pictures once for every JPEG XL viewer,
      only while somebody watches in JPEG XL. Needs an ffmpeg with
      libjxl; see the next point.
    - If the camera PC's ffmpeg can't make JPEG XL, telnetvision.exe
      downloads one that can, once (about 90 MB, into the ffmpeg-jxl
      folder next to it), and uses it for the JPEG XL pictures.
      JXL_DOWNLOAD=0 turns that off.
    - The web page shows JPEG XL too: with the browser's own decoder
      when it has one, else with libjxl as WebAssembly (jSquash).
    - New camera PC settings JXL_WIDTH (320), JXL_QUALITY (75) and
      JXL_DOWNLOAD (1); new tvserver.ini setting  jxl = on.


VERSION 1.2.0
-------------

Camera PC (telnetvision.exe)

  Screens
    - SOURCE=screen1, screen2, ... sends one monitor (1 is the main one,
      then left to right). SOURCE=screen still sends all of them.
    - SOURCE=window:<part of a title> sends one window.
    - SOURCE=screen:X,Y,WxH sends any area of the desktop.
    - telnetvision.exe --list-devices lists the screens with their sizes
      and positions, and --setup offers each one.

  Music
    - Songs (mp3, flac, ogg, opus, m4a, wav, wma, ...), folders of music,
      playlists of songs and internet radio play with a music visualizer
      as the picture: 12 looks in the spirit of Milkdrop that move with
      the bass, mids, treble and beats, blending into a new look now and
      then. V switches to the next look.
    - Songs' artist and title tags show in viewers' title bar.
    - SOURCE=visualizer shows the visualizer for the microphone or
      line-in (AUDIO_SOURCE).
    - New settings: VISUALIZER (auto, or the look to start on) and
      VIZ_SECONDS (how often it changes; 0 = only with V).

  YouTube
    - Each video is downloaded completely before it plays, and the next
      one downloads while it plays (one at a time), so the network can't
      interrupt it. Live streams are still streamed. New setting:
      YOUTUBE_PREFETCH (1 = on, the default).
    - Works with YouTube's separate picture and sound streams (fixes
      "Requested format is not available").
    - Streamed sound is fetched in small pieces with retries, so it no
      longer cuts out partway ("Error during demuxing: I/O error"); if it
      does stop, playback picks up again from the same spot.
    - A link to a video inside a playlist (watch?v=...&list=...) plays
      the whole playlist, starting from that video.
    - Clearer advice when YouTube refuses (update yt-dlp, install Deno).

  Sixel
    - Sixel viewers now get the camera PC's sharp picture every frame.
      Before, a timing slip meant most frames fell back to the ordinary
      80-wide picture, so High and Medium detail often looked blocky.
      For sharper sixel still, set SIXEL_WIDTH=320.

  Keyboard
    - Paste with Ctrl+V, Shift+Insert or a right-click: what you copied
      (a YouTube link, a path) goes on the Play line, or into the line
      you're typing.

Server (tvserver.exe), BBS door (door.exe) and relay (service.exe)

  - No changes apart from the version number.
